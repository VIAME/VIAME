# --- CUDA, pinned to the major this was built against ----------------------
# These are declared, and the reasoning that said they should not be was
# wrong. It ran: "which CUDA arrives is torch's decision, and pinning a major
# here would fight it." What actually happens is that torch's decision need
# not match ours. A clean `pip install` of this wheel brought
# `torch 2.14.0+cu130`, whose wheels provide `libcudart.so.13` in a
# consolidated `nvidia/cu13/lib`; this build needs `libcudart.so.12` under
# the per-component `nvidia/cuda_runtime/lib`. Nothing failed loudly -- the
# loader fell back to a system CUDA 12 that happened to be installed, which
# is precisely the dependency this was all meant to remove.
#
# So the CUDA major is ours to declare, because it is a property of how the
# binaries were compiled. `cu12` here must match `CUDA_TOOLKIT_ROOT_DIR` in
# the build; the wheel's RUNPATH points at these packages' layout.
#
# They coexist with a torch that chose a different major -- different package
# names, different directories -- at the cost of two CUDA runtimes on disk.
# The alternative, constraining torch to a cu12 release, pins a torch version
# to a CUDA choice upstream re-makes every release.
nvidia-cuda-runtime-cu12
nvidia-cublas-cu12
nvidia-curand-cu12
nvidia-cudnn-cu12
