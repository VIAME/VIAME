# Conversion review fixes — 2026-09-26

All nine reproduced findings in [the review](2026-09-26-conversion-review.md)
are addressed. This records the validation and remaining limits; the original
review describes the pre-fix snapshot.

## Main first

Main also returned zero frames for some Matroska files, but for a different
reason: its FFmpeg reader used stream duration even when only container
duration was available. KWIVER commit `3bcc4b3ff` adds that fallback and a
regression fixture. The new test fails against the old implementation; all
26 FFmpeg reader tests pass with the fix.

Main commits `7d2093306` and `8771afa69` fix the SLEAP test fixture and update
the KWIVER pin. After incorporating the intervening upstream changes, main
was pushed to `origin/main` at `2a359fb4e`. The KWIVER commit was pushed to
Kitware/kwiver's `viame/main` branch first.

Lite merge `9d2d4d7c4` incorporates main in the reduced source layout. The
new adaptive tracker trainer uses a small full-pivot solver in place of
Eigen. Its ranks agree with Eigen on 10,000 affine normal-equation systems
(6,666 full rank and 3,334 deficient); maximum solution difference was
2.2e-19. The trainer, training applet and pipeline utilities compile, and the
four pipeline utility tests pass against the merged implementation.

## Lite fixes

- **Resize (findings 1, 2, 9):** Python now uses the OpenCV pixel grid. Area
  resizing weights partial pixels and preserves float constants, including
  its distinct enlargement rule. ONNX preprocessing honors nearest, linear,
  cubic and area selection. C++ VXL callers retain their original grid.
- **Concurrency (3):** kernel argument conversion and Python result creation
  retain the GIL; native computation releases it. The stateful background
  model has a separate mutex, acquired after releasing the GIL.
- **Video (4, 5):** seeks rebuild the filter graph and decode through it.
  Frame counts use a separate decoder and are cached. Timestamp origins are
  established even if the caller does not ask for a timestamp, and stored
  in seconds so filter time-base changes do not corrupt them.
- **Image I/O and SLEAP (6, 7, 8):** grayscale uint16 and RGBA images survive
  PNG round trips. Decoded arrays are writable. Successful image writes
  return True, allowing SLEAP crop export to continue. The lite test fixture
  retains access to its native image kernels. JPEG writes use quality 95,
  matching the previous OpenCV default.

## Validation

Validation used an isolated source checkout and privately compiled kernels,
with existing installed dependencies. Shared build and install outputs were
not rebuilt or replaced.

- **286 Python tests pass:** 212 image-kernel/image-I/O/video tests, 35 tests
  covering the upstream tracker, RF-DETR and interactive prompt changes,
  24 SLEAP unit tests, and 15 video golden tests.
- **76 C++ tests pass:** 72 filter/color/warp/VXL-kernel tests and four
  pipeline utility tests.
- **300 resize comparisons** against locally installed OpenCV 5: five input
  shapes, five output shapes, three dtypes and four interpolation modes.
  Tested uint8 nearest, bilinear and area outputs match exactly. Cubic byte
  and uint16 errors are at most one level; float error is below 2e-6 for
  inputs in [0, 1].
- The original review probe, run with `--working-tree`, confirms successful
  real SLEAP crop export, writable decode/draw, preserved alpha and uint16,
  seek landing at 1.4 seconds followed by 1.5 seconds, and a count of 12
  during playback without changing the next timestamp of 0.3 seconds.
- Seek tests cover default deinterlacing, horizontal flipping, no additional
  filter, uint8 and 10-bit video, wall-clock and relative timestamps,
  backward seeks, and seeking after EOF. Concurrency tests cover both GIL
  release and simultaneous background-model updates.

## Performance

Median of seven warmed calls on the same host, 1080p input, Release builds;
OpenCV used one thread. These are kernel microbenchmarks, not model accuracy
or whole-pipeline throughput measurements.

| Operation | Before (ms) | After (ms) | OpenCV (ms) |
|---|---:|---:|---:|
| RGB resize to 640 × 360 | 8.61 | 2.74 | 0.64 |
| RGB area resize to 640 × 360 | 12.07 | 12.04 | 3.33 |
| RGB to grayscale | 12.10 | 4.51 | 0.81 |
| Grayscale Gaussian, 17 taps, sigma 2.5 | 181.83 | 39.48 | 4.53 |

Resize now caches only two horizontally filtered rows. Grayscale and output
copies access row pointers directly. Separable filtering handles borders
only at the edges and traverses pixels in its inner accumulation loops.
The largest observed pause in a second Python thread during a 31-tap blur
fell from 329 ms to 2.14 ms.

OpenCV remains faster in these cases. Area resizing is now correct but has
no measured speed gain. More optimization is needed before claiming that
lite is faster across these operations. This pass did not run full model
training or detector-accuracy comparisons. Pillow still cannot encode
multichannel uint16 images through this helper; those inputs raise instead
of silently losing their high bits. Float display images retain the helper's
existing conversion to uint8.
