# Phase 8: replace the kwiver-derived infrastructure

Goal: everything under `library/` is ours; kwiversys, cereal, castxml,
and the kwiver CMake macros are gone. References: lite-removals.md §5,
lite-build-system.md §3-5.

### P8-T01 Hand-written python bindings for `core_types`
Depends: P6-T06, P7-T09
Do:
- `core_types/`: pybind11 modules alongside the C++ for the types listed in lite-library-layout.md §1 with numpy buffer views for `image`, descriptor, matrices. Preserve the python API surface used by VIAME (`grep -rho "kwiver.vital.types.[A-Za-z_]*" library tools tests | sort -u` is the required list, plus methods used in those files).
- Replace the copied `python/kwiver/vital/types` bindings; module names unchanged (`kwiver.vital.types`).
Done when:
- pytest for types passes; all python plugins import.

### P8-T02 Hand-written algorithm trampolines (castxml gone)
Depends: P8-T01
Do:
- `algorithm_framework/algo/`: trampolines for the 18 interfaces python implements (list in lite-removals.md §5 python row; regenerate with `grep -rho "kwiver.vital.algo import [A-Za-z_, ]*"`), plus `algorithm_factory`, `config` bindings. Delete `cmake/kwiver_compat/` castxml logic and `castxml`/`pygccxml` from lock files.
Done when:
- Build has no castxml step; every python algorithm registers; BASELINE passes.

### P8-T03 Static registry replaces the plugin loader
Depends: P8-T02
Do:
- `algorithm_framework/registry/`: `registry` (interface -> name -> factory, alias table, attributes incl. origin library and python import path), `register_builtins()` generated by CMake from every `viame_add_library(... REGISTER)` in DAG order, python factory kind that stores an import path and imports on first `create()`.
- Build: fold all `viame_<name>` targets into one shared `libviame`; the `viame` executable and the `viame._core` extension link it; delete the `viame_<name>_plugin` module targets and `lib/viame/plugins`. Keep `viame_<name>` as OBJECT libraries for tests.
- Delete `vital/plugin_management`, `plugin_loader` uses, `KWIVER_PLUGIN_PATH` handling, `SPROKIT_MODULE_PATH`, `SPROKIT_PYTHON_MODULES`. Keep `PLUGGABLE_IMPL`/`PARAM` macros compiling against the new registry.
- `registry-dump` reads the alias table and lists lazy python entries without importing them.
- External plugin hook only if open decision 10 = keep: `external_plugins.cxx` (~150 lines) iterating `VIAME_PLUGIN_PATH` and calling `viame_register_plugin(registry&)`; otherwise no dlopen code at all.
Done when:
- BASELINE passes; `ls build/install/lib/viame/plugins` does not exist; `algorithm_framework/registry` < 1200 lines; `git grep -n "plugin_loader\|KWIVER_PLUGIN_PATH\|SPROKIT_PYTHON_MODULES" -- library tools cmake` empty.
